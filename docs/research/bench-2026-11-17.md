## Setup

- **PC:** 12th Gen Intel Core i7-12650H (16 threads), Windows 11. 48 kHz, 128-sample blocks, stereo; the left output channel is analysed.
- **CPU:** percent of one core in the process call, median of 5 runs of 20 s, with a ratio to Fancy Comp at its defaults timed in the same session. The ratio is the figure to compare between runs.
- **Logs:** no warnings in any measured run, and no values found by search or read back.

## Multiband: 4 bands, 4:1 at -20 dB, attack 10 ms, release 100 ms (Convergence Free)

Fancy MultiComp 1.6.0 against Convergence 1.1.2 (Cut Through Recordings, free), from `%COMMONPROGRAMFILES%\VST3\Cut Through Recordings Convergence-64.vst3`, with `tools/bench/examples/multiband.json` as of commit `68e7c2f`. Each plugin has 4 bands with crossovers at 120 Hz, 1.2 kHz and 6 kHz, and every band is set to 4:1 at -20 dB, attack 10 ms and release 100 ms. Convergence's settings are made on each band, and both plugins displayed every value as asked. Fancy MultiComp keeps its other defaults: knee 6 dB, RMS size 5 ms and Auto make-up off. Convergence has no matching knee or detector controls, so the amount of compression isn't matched. Fancy Comp's reference in this session: 0.88 %.

| | Fancy MultiComp | Convergence Free |
|---|---|---|
| CPU, mean | 2.25 % | 4.14 % |
| CPU, 99th percentile | 5.5 % | 9.2 % |
| CPU, worst block | 9.6 % | 19.0 % |
| Ratio to Fancy Comp | 2.56 | 4.71 |
| Latency, reported / measured | 0 / 1 sample | 0 / 3 samples |
| Gain at -10 dBFS, mid-band (sweep) | about -5 dB | about -3.8 dB |
| Response at a crossover (sweep at -10 dBFS) | up to about 3.7 dB less reduction at each crossover | 6.4 dB notch at 1.2 kHz, small ripples at 120 Hz and 6 kHz |
| THD, 100 Hz at -30 / -20 dBFS (below threshold) | -175 / -176 dB | -97 / -98 dB |
| THD, 100 Hz at -10 / 0 dBFS | -69.5 / -65.3 dB (0.034 / 0.054 %) | -43.2 / -43.4 dB (0.69 / 0.67 %) |
| THD, 1 kHz at -10 / 0 dBFS | -109 / -105 dB | -62.4 / -62.3 dB (0.076 %) |
| THD+N below threshold | -150 dB | -70 to -97 dB |
| Loudest alias, 5 kHz / 10 kHz at 0 dBFS | -140 / -139 dB relative | -88.5 / -79.5 dB relative (35 and 59 aliases) |
| Clicks, Band 2 Threshold jumping -40 to -10 dB 20 times a second | none (peak -97 dBFS) | 38 bursts of 40, up to -24.7 dBFS |

- **CPU:** Fancy MultiComp costs a little over half of Convergence's mean CPU, and its worst block is half Convergence's.
- **Distortion:** Convergence adds about 0.7 % THD on 100 Hz once it compresses, about 20 times ours. It also adds 0.076 % on 1 kHz and has noise of -70 to -97 dB even below threshold. Ours is rounding error until it compresses, and stays under 0.06 %.
- **Aliasing:** Convergence aliases 50 to 60 dB louder than Fancy MultiComp, which is at the analysis floor.
- **Automation:** Convergence clicks audibly when a band's threshold jumps. Fancy MultiComp smooths it.
- **The crossovers:** Convergence's 6.4 dB notch at 1.2 kHz means its bands don't sum flat there. Fancy MultiComp's rises at each crossover come from the sweep being a single sine: at a crossover it's split between two bands, so each band's detector sees it quieter and compresses less. Its bands sum within 0.03 dB with no gain change (CI test).
- **Low bass:** Fancy MultiComp compresses a little more below 50 Hz (about -6 dB at 20 Hz, against -5 dB mid-band). This is likely its 5 ms RMS detector following single cycles of very low notes, which also explains why its THD is higher at 100 Hz than at 1 kHz.
- **The amount of compression differs by design,** from the knee and detector, as noted in Setup. It isn't a fault in either plugin.

## Multiband: 3 bands at 425 Hz and 5.5 kHz (KolinMB)

Fancy MultiComp 1.6.0 against KolinMB 1.0.0 (Analog Obsession, free), `multiband-kolin.json`, on KolinMB's three bands: attack 10 ms, release 400 ms. KolinMB has no threshold or ratio. Each band's Input drives it (Low 14, Mid 30, High 12 dB), chosen to match Fancy's 4:1 at -20 dB at 1 kHz only. Its band Outputs only go up from 0 dB, so the -14, -30 and -12 dB asked for landed on 0 dB. **CPU, latency, aliasing and clicks compare like for like; the response and THD show each plugin's character, not the same settings.** Fancy Comp's reference in this session: 0.82 %.

| | Fancy MultiComp | KolinMB |
|---|---|---|
| CPU, mean | 1.48 % | 1.72 % |
| CPU, 99th percentile | 3.3 % | 3.8 % |
| CPU, worst block | 9.8 % | 10.7 % |
| Ratio to Fancy Comp | 1.79 | 2.08 |
| Latency, reported / measured | 0 / 1 sample | 0 / 0 |
| Gain at -10 dBFS, 1 kHz (sine) | -4.9 dB | -3.6 dB |
| Gain at -10 dBFS, 100 Hz / 10 kHz (sweep) | -5.6 / -4.5 dB | -16.4 / -20.3 dB |
| THD, 100 Hz at -30 dBFS (below threshold) | -173 dB | -58 dB (0.13 %) |
| THD, 100 Hz at -10 / 0 dBFS | -75.4 / -75.4 dB (0.017 %) | -40.1 / -34.5 dB (0.99 / 1.9 %) |
| THD, 1 kHz at -10 / 0 dBFS | -115 / -116 dB | -63.8 / -48.5 dB (0.064 / 0.38 %) |
| Loudest alias, 5 kHz / 10 kHz at 0 dBFS | -142 / -148 dB relative | -80 / -81 dB relative (306 and 178 aliases) |
| Clicks, 40 jumps | none on Band 2 Threshold -40 to -10 dB (peak -104.5 dBFS) | 38 bursts on Mid Input 20 to 30 dB, up to -50 dBFS |

- **CPU:** on three bands Fancy MultiComp costs a little less than KolinMB (1.48 against 1.72 %).
- **Character:** KolinMB is a coloured, analogue-style compressor. It distorts even below threshold (0.13 % at 100 Hz, -30 dBFS) and reaches 1.9 % at 100 Hz, 0 dBFS. Fancy MultiComp stays under 0.02 %.
- **The drives match at 1 kHz only.** KolinMB's low and high bands compress 10 to 15 dB harder than its mid band at the same input, so the 100 Hz and 10 kHz rows don't compare like for like.
- **Clicks:** KolinMB clicks when a band's Input jumps, and Fancy MultiComp doesn't. That's a level jump rather than a threshold jump, so it's not quite the same test.

## Spectral noise reduction, 18 dB (Bertom Denoiser Classic)

Fancy FIR 1.6.0 in Subtract mode, tracking the noise itself (Adaptive, adapt speed 2 s, Reduction -18 dB), against Bertom Denoiser Classic 3.0.11 (free, pay what you want; threshold -60 dB, each of its six ranges -18 dB), `spectral.json`. Denoiser Classic isn't FFT-based, so it has no latency. The test signals are sines and sweeps with no noise in them, so these figures show what each one does to clean audio, not how well it removes noise. Fancy Comp's reference in this session: 0.82 %.

| | Fancy FIR | Bertom Denoiser Classic |
|---|---|---|
| CPU, mean | 1.98 % | 0.43 % |
| CPU, 99th percentile | 16.5 % | 1.1 % |
| CPU, worst block | 97.7 % | 20.6 % |
| Ratio to Fancy Comp | 2.42 | 0.53 |
| Latency, reported / measured | 4096 / 4096 samples (85 ms) | 0 / 0 |
| Response, sweep at -20 dBFS | flat within 0.01 dB | -0.3 to -2.0 dB |
| Level change, sine at -30 dBFS | none | -1.8 to -4.5 dB |
| THD, 100 Hz at -20 / -6 dBFS | -118 / -124 dB | -48.2 / -44.9 dB (0.39 / 0.57 %) |
| THD, 1 kHz and 5 kHz, any level | -148 to -165 dB | -66 to -101 dB |
| THD+N, any frequency and level | -74 to -89 dB | -61 to -67 dB |
| Loudest component near the tone, 5 kHz / 10 kHz at -6 dBFS | -73.9 / -73.2 dB relative | -79.9 / -79.8 dB relative |
| Clicks, Reduction / Range 1 jumping -6 to -24 dB, 40 jumps | none | none |

- **CPU:** Denoiser Classic costs about a fifth of FIR's mean, as expected from a filter-bank design against FIR's FFTs. FIR's 99th percentile (16.5 %) matches CI's paced figures for its spectral modes (11 to 19 %, `docs/measurements/fir-q27.txt`), since the FFT work lands on one block in every few. **Its worst block, 97.7 % of the block's time, is far above CI's worst (20 to 26 %)** and close to an audio dropout. Fancy Comp's worst block in the same session (10.8 %) was also higher than in the other sessions that day (6.5 to 8.7 %), so the PC was busy, and one run can't tell whether FIR or the PC caused it. Worth re-running before drawing a conclusion.
- **On clean audio FIR is transparent:** a flat response, no level change and THD at rounding error. Its THD+N, -74 to -89 dB, is the floor left by the spectral processing, 10 to 20 dB below Bertom's.
- **Denoiser Classic acts like a multiband expander:** it turns quiet tones down by up to 4.5 dB and distorts bass (0.57 % at 100 Hz, -6 dBFS), as its gain moves within each cycle.
- **The "aliasing" readings are processing sidebands,** hundreds of small components spread near the tone in both plugins (174 to 183 for FIR, 545 to 894 for Bertom), not aliasing. FIR's loudest is 6 dB above Bertom's, and both total about -70 dB.
- **Not measured:** how much noise each one removes and how it sounds. That needs a noisy recording and listening, not these test signals.
